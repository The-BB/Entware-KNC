    realtek: l3: report IPv4 offload state per route
    
    The IPv4 path sets RTNH_F_OFFLOAD on the fib_nh when a route is added
    and clears it when one is deleted. Every route through the same gateway
    shares that fib_nh, so the flag says nothing about the route it is
    printed on. On RTL9303, with 600 prefix routes through one gateway, all
    600 show as offloaded although the table holds 476 of them. Delete the
    first 150 and the other 450 show nothing, although 350 of them still
    forward in hardware. Routes whose entry sends the traffic to the CPU,
    because their gateway is gone or not resolved yet, show as offloaded
    too.
    
    Keep the route's fib_info and set the flags on the route alias from the
    code that programs it, as the IPv6 path does: offload when the route
    forwards in hardware, trap when its entry sends the traffic to the CPU
    (gateway gone or not resolved yet, a local address, a connected prefix),
    offload_failed when the table has no room for it. The same 600 routes
    then show 476 offload and 124 offload_failed, and after the delete 350
    offload and 100 offload_failed.
