    realtek: eth: drop the RTL839x L2 notification code
    
    On RTL839x the ethernet driver turns on the L2 notification engine and
    passes its learn and age events to the bridge. It reports them against
    the conduit, which is not a bridge port, so br_switchdev_event() drops
    every one of them. Nothing else reads them. RTL838x, RTL930x and
    RTL931x run without this code.
    
    Drop the notification setup, its interrupt handling and ring, and the
    NIC reset code that preserved them. The vendor SDK defines no
    interrupt in the mask bits this code also set on the other families:
    bits 20-22 of DMA_IF_INTR_MSK on RTL838x, bits 4-6 of
    DMA_IF_INTR_TX_DONE_MSK on RTL930x and RTL931x.
    
    Tested on an HPE 1920-48G (RTL8393):
    - after boot, L2_NOTIFICATION_CTRL reads 0x00001002 (engine off) and
      DMA_IF_INTR_MSK has none of bits 20-22 set;
    - the switch still learns the hosts behind its ports;
    - a route offloaded with IPv4 forwarding off still delivers 8 of 8
      echoes.
    
    This does not stop the resets on a full bridge fdb show on that switch:
    they happen with or without this code.
