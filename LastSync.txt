    ramips: tp-link: use a temporary file per image for OKLI images
    
    The squashfs images of the TP-Link RE200 v1 and RE210 v1 differ between
    builds; the uncompressed kernel of the RE200 one was 271 bytes larger,
    from its device tree on:
    
      -00001040: 6d00 0080 00cb 1a9e 0000 0000 0000 006f
      +00001040: 6d00 0080 00da 1b9e 0000 0000 0000 006f
    
    The RE210 device tree is exactly 271 bytes larger than the RE200 one, so
    the RE200 image carried the kernel of the RE210.
    
    tplink-v1-okli-image puts kernel and rootfs together in
    $(IMAGE_ROOTFS).factory or .sysupgrade, a name shared by all devices with
    the same rootfs. Both devices are built at the same time, so one can
    overwrite the file of the other between cp, cat and mktplinkfw, and an
    image can end up with the kernel and device tree of the other device.
